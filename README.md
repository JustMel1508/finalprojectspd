# Путешествие по истории Казахстана

Локальная браузерная образовательная 2D-игра. Десять глав от XV века до 1991 года: управляемый персонаж, 20 вымышленных NPC, 20 QuizTask, 10 MapTask, обучение и проверка знаний, сохранение, история и TXT-экспорт. Java выполняет игровую логику и все шесть паттернов; Canvas/SVG и обычный JavaScript отображают состояние.

Команда: **Бахыт Карима, Адай Аида, Казбекова Айша**. Репозиторий: https://github.com/JustMel1508/finalprojectspd . Техническая реализация создана с AI-помощью Codex; самостоятельный вклад и защита студентов не подтверждены. См. [CONTRIBUTIONS.md](CONTRIBUTIONS.md).

## Быстрый запуск

Нужен **JDK 17+**, не только JRE. При первой сборке нужны интернет и доступ к Maven Central. Maven устанавливать отдельно не требуется: Wrapper закрепляет 3.9.12. После сборки JAR игра работает без сети, CDN и внешних API.

Windows PowerShell из папки проекта:

```powershell
$env:JAVA_HOME = 'C:\Users\aikli\.jdks\ms-17.0.18'
.\mvnw.cmd verify
& "$env:JAVA_HOME\bin\java.exe" -jar .\target\history-journey-1.0.0.jar
```

Также доступны `./build.ps1` и `./run.ps1`. Скрипты находят JDK 17 в `.jdks`, если JAVA_HOME не задан. Если политика PowerShell запрещает запуск скриптов, используйте команды выше; изменять системную политику не требуется.

Linux/macOS (JAVA_HOME указывает на установленный JDK 17+):

```sh
chmod +x mvnw
./mvnw verify
java -jar target/history-journey-1.0.0.jar
```

Открыть **http://127.0.0.1:8080**. Остановка сервера — Ctrl+C. Другой порт: `--server.port=8081`. Другие сохранения: `--game.data-dir=/absolute/path/data` или `GAME_DATA_DIR`. Пример PowerShell: `./run.ps1 -Port 8081 -DataDir ./data-demo`.

В проверенной среде системный `java` — Java 8; он непригоден. Реальная сборка: Microsoft OpenJDK 17.0.18, Maven 3.9.12, Spring Boot 3.5.7, JUnit Jupiter 5.12.2. Язык/байткод — Java 17. Python и PlantUML нужны только для дополнительных проверок и пересоздания документации.

## Как пройти

1. Выберите демонстрационный профиль «Путешественник» либо создайте свой: имя 1–40 символов, герой/героиня. Кнопка имени сверху открывает редактирование и выбор другого профиля.
2. На карте выберите доступный уровень и режим. Новый профиль получает первый уровень; последующие открываются последовательно. Название и дата на обзорной карте раскрываются после успешного прохождения.
3. В первой попытке есть короткий пролог. Двигайтесь WASD/стрелками (также русская раскладка), экранными стрелками или укажите точку на Canvas. Нельзя проходить сквозь препятствия. E/У либо «Поговорить» открывает разговор в радиусе NPC.
4. Выслушайте обоих собеседников и нажмите «Записать и продолжить». Затем откройте задания и прочитайте историческую справку. Она отделяет знания жителей сцены от позднейших событий.
5. **Обучение:** неверный ответ даёт подсказку и повтор; для успеха нужно правильно выполнить все задания. Счётчик ответов и ошибок учитывает повторы, число заданий остаётся 3.
6. **Проверка знаний:** один ответ на задание; правильность скрыта до завершения. Только три верных ответа дают успех. Неуспешная попытка остаётся в истории.
7. Нажмите «Завершить и сохранить», просмотрите результат и скачайте TXT. Итог содержит дату/время UTC, режим, число заданий, верные ответы, ошибки, число ответов и объяснения.
8. Через карту можно продолжить ACTIVE-попытку. После закрытия браузера и перезапуска Java сохраняются NPC и ответы; позиция персонажа возвращается в безопасную стартовую точку.
9. Отмена требует подтверждения и сохраняет освоенный прогресс. История содержит завершённые, активную и отменённые попытки. «Мой итог» показывает уникальные главы и повторы отдельно; после 10/10 появляется общий финал и экспорт.

Во время диалога/задания/модального окна движение остановлено; при потере фокуса клавиши сбрасываются. При вводе имени WASD работают как текст. На узком экране панели переходят в одну колонку, доступны экранные кнопки. Фактическая ручная проверка браузера остаётся в [списке проверок](docs/TEST_SCENARIOS.md).

## Данные и модель доверия

`data/save.json` создаётся при первом запуске, формат версии 1. Игровые определения находятся внутри JAR в `resources/content`, пользовательское состояние с ними не смешивается. Клиент не получает правильные ответы или скрытые будущие заголовки через обзорные DTO.

Это однопользовательское локальное учебное приложение без паролей и аутентификации. ID профиля выбирает данные, но не является секретом. Доступ к попыткам проверяется на соответствие выбранному профилю; это не изоляция от владельца компьютера. API разговоров не доказывает физическую позицию на Canvas: позиция относится к интерфейсу. Сервер проверяет посещение NPC, порядок заданий, варианты, допуск к главе, режим и состояние. Не публикуйте сервер в интернет с такой моделью доверия.

Изменения сериализованы, применяются к отдельной копии снимка и фиксируются `temp → force → ATOMIC_MOVE`. Память обновляется после записи; на ошибку записи — 503 и прежнее состояние. Файловая система должна поддерживать атомарное переименование. Один Java-процесс обслуживает папку данных: одновременный запуск двух процессов с одной папкой не поддерживается.

При повреждении/неподдерживаемой версии JSON исходный файл остаётся нетронутым; `/api/health` и экран показывают инструкцию. Остановите сервер, сохраните копию `save.json`, исправьте либо переименуйте повреждённый файл и перезапустите. Новая игра появится только после явного удаления/перемещения файла пользователем.

Каждый ответ имеет UUID requestId. При сетевой ошибке повторите тот же вариант: интерфейс сохранит requestId до успеха. Новый ответ после подсказки получает новый UUID. Повтор одного UUID с другим телом отклоняется. Завершение и отмена идемпотентны; завершённую попытку изменить нельзя.

## Архитектура и паттерны

| Pattern | Problem it solves | Main classes/interfaces | How to demonstrate it | Responsible student |
| --- | --- | --- | --- | --- |
| Builder | Согласованная глава из данных | ChapterBuilder, ChapterDefinition, Chapter | Запуск загружает 10 глав; тест отклоняет неполный Builder | Бахыт Карима (план) |
| Factory Method | Разные типы задания при единой подготовке | TaskCreator, QuizTaskCreator, MapTaskCreator, Task | После диалогов два вопроса и карта | Бахыт Карима (план) |
| Facade | Координация полного игрового действия | GameFacade, ProfileService, AttemptService, ResultService | Начало → диалог → ответ → результат → экспорт | Адай Аида (план) |
| Strategy | Разные правила обработки ответов | AnswerCheckingStrategy, LearningStrategy, AssessmentStrategy | Одна ошибка: подсказка/повтор или окончательный ответ | Адай Аида (план) |
| Observer | Прогресс и статистика при завершении | ChapterCompletedPublisher, ChapterCompletedObserver, ProgressObserver, CompletionStatisticsObserver | Успех открывает уровень, неуспех увеличивает failed | Казбекова Айша (план) |
| Visitor | Статистика и TXT для разных результатов | TaskResult, QuizResult, MapTaskResult, ResultVisitor, StatisticsVisitor, TextReportVisitor | Экран результата и скачивание TXT | Казбекова Айша (план) |

`web/` — DTO/валидация/HTTP; `service/` — сценарии; `model/` — сущности; `content/` и `task/` — Builder/Factory Method; `strategy/`, `event/`, `result/` — поведение; `storage/` — JSON; `static/` — интерфейс. Состояния: `ACTIVE → COMPLETED` или `ACTIVE → CANCELLED`. COMPLETED хранит passed отдельно. Методы фасада возвращают разрешённые DTO, а не определения контента.

SOLID: SRP разделяет хранение, обработку ответов и представления; OCP позволяет добавить Strategy/Observer/Visitor; LSP требует соблюдения контрактов Task и стратегий; ISP — небольшие интерфейсы; DIP — GameFacade зависит от GameRepository. Ограничения: Facade пока создаёт небольшие сервисы и подписчиков сам; добавление нового типа Task требует расширения Visitor, DTO/контента и фабрики.

## Проверки

```powershell
.\mvnw.cmd verify
python .\tools\process_smoke.py --java "$env:JAVA_HOME\bin\java.exe"
node --check .\src\main\resources\static\app.js
node .\tools\ui_logic_test.cjs
```

Тесты: [GameLogicTest.java](src/test/java/edu/historyjourney/GameLogicTest.java), [HttpApiTest.java](src/test/java/edu/historyjourney/HttpApiTest.java). Хранение изолировано временными папками. `process_smoke.py` запускает отдельные Java-процессы, проходит 10 глав, останавливает и перезапускает JAR и проверяет повреждённое сохранение. Результаты — `docs/verification`. Полный список фактически выполненных и ожидающих проверок: [TEST_SCENARIOS.md](docs/TEST_SCENARIOS.md).

Простой воспроизводимый ручной сценарий: новый профиль → уровень 1 → обучение → оба NPC → неверный первый ответ → правильный повтор → второй вопрос → карта → завершение → TXT → перезапуск → продолжить уровень 2. Для проверки финала пройти все десять глав. Правильные ответы для проверяющего находятся только в серверных JSON-файлах.

## Комплект и документация

- `docs/REQUIREMENTS_MATRIX.md` — сверка с оригинальным заданием и расширенным запросом.
- `docs/HISTORICAL_SOURCES.md`, `docs/ASSET_PROVENANCE.md`, `THIRD_PARTY_NOTICES.md` — проверенные источники и происхождение.
- `docs/uml/` — редактируемые `.puml`, SVG и PNG общей архитектуры, паттернов и последовательности.
- `docs/report/REPORT.md` — редактируемый отчёт; `output/pdf/history-journey-report.pdf` — PDF.
- `docs/defense/` — материалы и самостоятельные упражнения для троих.
- `docs/PLAN.md` — план трёх недель и еженедельных демонстраций.
- `dist/source.zip` — исходники без личных сохранений, `.git` и загруженных инструментов; `dist/history-journey-1.0.0.jar` — исполняемый JAR.

Пакетируется `python tools/package_release.py`. Архив исходников включает Maven Wrapper, контент, тесты, инструкции, UML и отчёт. Для воспроизводимости полные версии зависимостей определяются pom и закреплённым Spring Boot parent; первый Maven-запуск скачивает их в локальный кеш.

## Развитие и статус

AI-наставник, генерация ответов и адаптивность не включены в игру. Future Work: проверяемый помощник со ссылками, дополнительные главы и новые стратегии после педагогической экспертизы.

Технические результаты и ограничения отражены в матрице; оценку выставляет преподаватель. Полностью сгенерированная реализация не заменяет требуемую самостоятельную разработку двух паттернов каждым студентом. Лицензия нового проекта командой ещё не выбрана; отсутствует автоматическое разрешение распространять чужие материалы. Тексты NPC — собственная учебная реконструкция, иллюстрации — оригинальный код, карта — public domain.
