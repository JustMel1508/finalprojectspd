# Адай Аида — Facade и Strategy

Это план самостоятельной подготовки; текущая реализация AI-assisted, личный вклад не подтверждён.

Facade: `service/GameFacade.java` — вход в use cases для GameController. Он связывает ProfileService, AttemptService, GameRepository, ContentCatalog, ResultService и ChapterCompletedPublisher. Контроллер проверяет DTO, фасад проверяет владение и координирует сценарий, repository фиксирует снимок. Польза: интерфейс вызывает небольшое число операций и не знает устройства хранения. Ограничение: фасад может разрастаться; предметные правила нужно продолжать выносить в модели/сервисы. Текущая сборка сервисов внутри фасада проста, но менее гибка, чем полная инъекция зависимостей.

Strategy: AnswerCheckingStrategy задаёт `check`, `canAdvance`, `feedback`. LearningStrategy допускает повтор после ошибки и даёт подсказку. AssessmentStrategy допускает единственный окончательный ответ и скрывает оценку. AnswerEvaluator переиспользует общую правильность и счётчики, а AttemptService выбирает стратегию по сохранённому Mode. Клиент не может поменять режим в активной попытке.

Демонстрация: ошибиться на первом вопросе в обучении → получить подсказку → повторить; затем новая проверка знаний → один ответ → следующее задание → правильность только после finish. Прямой API к закрытой главе или ранний finish должен получить 409. Покажите GameController → GameFacade.answer → repository.transaction → Strategy → persist → DTO. В ASSESSMENT ответ не содержит result до finish.

Тесты: `./mvnw.cmd -Dtest=GameLogicTest#learningHintRetryCountsOneTaskAndIdempotentRequest+assessmentHidesCorrectnessAndSavesFailure test`; HTTP-проверки — `./mvnw.cmd -Dtest=HttpApiTest test`.

Самостоятельная реализация: реализуйте оба правила по интерфейсу без копирования веток в контроллер и свой фасадный сценарий с транзакционным сохранением. Зафиксируйте личные тесты и коммиты. Сохраните честное описание использованного AI-кода.

Упражнение Strategy: разработать экспериментальную стратегию с максимум двумя ответами и отложенным раскрытием. Файлы: strategy/, Attempt.Mode, AttemptService, DTO/UI выбора режима и тесты. Сначала явно определите canAdvance после второго неверного ответа и критерий passed. Не меняйте два обязательных режима. Проверка: два неверных ответа закрывают задание, третий отвергается, прежние тесты проходят.

Упражнение Facade: добавить read-only операцию получения времени и числа посещённых NPC активной попытки через отдельный DTO. Файлы: GameFacade, GameController, тест HTTP. Проверка: для чужого профиля 404, корректная попытка возвращает только разрешённые поля, без answer keys.

Вопросы: почему Facade не заменяет все предметные сервисы? Где проходит граница транзакции? Что произойдёт при одинаковом requestId с другим телом? Почему повтор после сетевой ошибки нельзя считать новым ответом? Почему правильность проверяется на Java-сервере? Почему локальный выбор профиля не равен аутентификации?
